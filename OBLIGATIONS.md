# Obligations register

An **obligation** is something a session decided was owed and did not do. This file is the list of
them, what each one is waiting on, and whether anyone has decided anything about it since.

**Why it exists.** Every other register in this project mechanizes a *claim*: the control register
turns "roughly thirty controls" into a list a test reads by name, the phase verifiers run acceptance
criteria rather than reading a checkbox, and `tools/statement_inventory.py` resolves every identifier
named in prose. Nothing mechanized a *discharge*. Handovers carried a `What is owed` section, the
decision record carried a `Not checked` block, and whether an owed item was ever addressed depended
on the next session reading a document — which is the "somebody remembers" failure this project
mechanizes away everywhere else. Found by counting, at the end of phase 3, what this repository
verifies by machine and what it verifies by a reader (D126).

**What makes this list recoverable.** `tests/test_obligations.py` harvests every numbered item under
a `## What is owed` heading in every `sessions/HANDOVER-*.md` and requires each to appear below. An
owed item written into a handover and not registered turns the suite red. That is the difference
between this file and the reading it replaces: the reading was a result, this is a rule.

**Both directions.** A row naming a handover item that does not exist is equally loud — a source
renumbered or a section rewritten leaves rows asserting nothing, which is how the control register's
own line-numbered predecessor went stale before its author finished editing it.

**And on more than a number.** The harvest keyed on *(handover, item number)* alone until an
independent audit renamed an owed heading to a completely different obligation, kept its number, and
watched all ten tests stay green. The `anchor` column is a distinctive substring of the item's own
title, compared against the harvested heading — the same idiom the phase verifiers use to bind an
entry to a specification criterion, for the same reason: a position is not an identity.

## What a status means

- **open** — nobody has decided anything. The default, and the only status that needs no
  justification, because it claims nothing.
- **deferred** — somebody decided *not now*, and the row says **what would make it actionable**. A
  deferral with no trigger is an open item wearing a decision's clothes, which is the state this
  register exists to make visible. Enforced: a `deferred` row with no trigger fails.

  **A trigger is read against what has happened wherever it can be** (D166, P4-15). A trigger
  naming a tag the way `git tag --list <name>` shows it names an event this repository records:
  once the tag exists the row carries `fired` and the date, and a row claiming `fired` for a tag
  that does not exist is refused as well. A trigger nothing here can observe says `read by a
  person`, so relying on a reader is written down rather than implied. Acknowledging a fired
  trigger closes nothing; it records that the event the deferral waited for has happened.
- **closed** — done, and the row names **evidence**: a test, a decision id, or a commit. Enforced: a
  `closed` row with no evidence fails, and where the evidence names a test, that test must exist.

**There is deliberately no `wontfix`.** A decision never to do something is a decision, and this
project records those in `specs/voice-agent-eval-harness.decisions.md` — where it has to state a
fork, the options considered and the consequences. A status that let a row absorb that reasoning
would be a place for decisions to go unrecorded.

## What this register does NOT do

It does not know whether an obligation *should* be discharged, and it cannot. Every status here was
typed by somebody. What it removes is the failure where nobody notices an item exists — not the one
where somebody looks at it and is wrong.

It also does not cover `HOLDOUT-OBLIGATIONS.md`, which is its own register with its own discharge
rule: those entries may only be ticked by a session cleared to read held-out content, and that
condition has no analogue here. Its per-entry markers are checked by the same test module.

## On the first population

*(Written when there were eleven rows, before an independent audit of phase 3 added four. The
observations below are about the register's first day and are left in that tense; the four rows it
gained are `OB-12` to `OB-15`, all four deferred or open, all four naming phase 4.)*

**59**<!-- #obligation_rows --> rows, and **one of them is this register discharging itself**.
That is not a joke about bootstrapping: OB-10 is the obligation that produced the file, and if it were not registered here the
file would be an instance of the problem it was built to solve.

**Every `deferred` row names a phase**, which is the honest reading of most of what a phase hands
on: not "we forgot" but "the specification puts this later". A register that recorded those as `open`
would report every one of them as unaddressed, when what they are is scheduled.

The deferred count is deliberately not written here. The row count above is tagged because it is
computed from the table; a second quantity maintained by hand beside it would be the thing this
project de-quantifies rather than checks (D74), and the table is four lines away.

**Only OB-10 is `closed`**, and that is worth seeing on the first day rather than discovering later.
A register whose first population were mostly green would be one built to describe work already
done.
