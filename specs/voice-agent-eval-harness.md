## outcome
A reader can clone the repository and, **with no API key and no spend**, produce the complete evaluation report for a sixteen-call synthetic corpus<!-- #design_set_size --> — then walk any finding backwards through report → rubric entry → findings row → transcript line, and forwards through transcript → seeded defect → check → verdict. An engineer supplying their own key can run the same harness live, against their own transcripts, in either supported format. Measurable as: `uv run harness report` succeeds on a fresh clone with no credential present; every rubric entry's `traces_to` resolves to an existing findings row; every findings row carries a `detectable by` classification; the Tier A section of the report is byte-identical across runs and modes; and judge-versus-human agreement is reported on a held-out set whose labels were committed after the rubric-freeze tag.

## in scope
- [P1] A written **canonical event model** (`specs/event-model.md`) — the call record, the context record of what the agent could see before it spoke, the typed event stream with invocation and result as separate events linked by id, the closed vocabularies, and the two citation populations. **This is the contract**: nothing above the adapter line knows which platform a call came from.
- [P1] A written **transcript format specification** (`specs/transcript-format.md`) — one serialization of that model, and adapter 1's source format. Realistic wrapped text, because a format forbidding wrapping would design out the bug class the extraction tier exists to catch.
- [P1] **sixteen design-set transcripts**<!-- #design_set_size -->, originally authored under clean-room conditions, carrying seeded defects across both deterministic-detectable and judgment-requiring classes, including at least one prompt-injection attempt in caller speech. Which defects, and which are consciously not seeded, is governed by `specs/taxonomy-coverage.md` — the 35-item taxonomy and the W1–W35 known-weakness list, each item carrying a disposition. Without it a corpus could cover fifteen of thirty-five and nothing would say so.
- [P1] **Reference policy documents** (return and refund at minimum) as versioned corpus artifacts, retrieved in-call by a logged lookup.
- [P1] A **findings document in YAML** — one entry per finding, each with a stable `id`, `call_ref`, `owner` (`agent`/`platform`/`data`), `observation` (self-contained prose), `evidence` (a *list*, so fragments from different points in a call stay visibly separate), `consequence`, `detectable_by` (`assert`/`judge`/`human`) and `tier` (`defect`/`question`). **Eight keys, of which six cross the repository boundary**: the severity tool reads a finding to compare it against another finding, and needs neither which call it came from nor whose defect it is. `call_ref` and `owner` are harness-side, and `tools/check_spec_interface.py` declares that split rather than leaving its narrower list to be read as a stale copy — which is how an independent audit read it. YAML because evidence holds verbatim multi-line quotes that a Markdown table cell cannot carry and CSV quoting handles badly. A Markdown view is generated from it for reading; the YAML is the source of truth.
- [P1] **Severity scores** for the design-set findings, produced by the external comparative-judgment tool, which emits a **separate severity file keyed by finding id** at `corpus/findings.severity.json` carrying, at minimum, `schema_version`, `anchor_set_version`, `comparison_log_hash`, `run_id`, `calibration`, `severities`, `unplaced` and `cuts`, and **on every row** `content_hash`, `appearances` and `informative` alongside `id`, `severity` and `theta`. Extra fields are tolerated; a missing one is a break, and the schema version is checked by name rather than treated as a floor — because tolerating extras means absence is legal, so a check for a field that tolerated its absence would assert nothing. **The row fields arrived at schema 2 and each closes a gap this project measured rather than supposed.** `content_hash` is the text the band was placed on: without it a finding edited after export keeps a band describing wording nobody compared, which is what `e28650c` did to three judged findings on 2026-09-07, unnoticed for four days (D140). `appearances` and `informative` are how decisively it was placed: a tie is a judgment the tool keeps and the fit excludes, so ten appearances with eight ties is a band resting on two results — the row whose position moves furthest when one more comparison arrives, which is how placing a single new finding silently re-banded three others (D144). The harness recomputes `content_hash` from the gold set and compares, which is a **second definition of one hash in two repositories** — rejected at D82 as drift-prone, and correct then, because nothing compared them; compared on every run it reports that drift as the same red as a moved finding (D148). **`cuts` arrived at schema 3 and closes a gap of the same kind.** A band cut is stored as the adjacent pair of findings either side of it and banded by their midpoint, so it can stop separating neighbors with nothing refusing it, which is how placing F-90 re-banded findings with nothing reporting it (D144). Each entry names a cut's anchors, the gap between their `theta` values and the findings strictly between them, most severe first. The tool reports a wide cut and refuses nothing for it; **the harness re-derives every between-set and gap from the rows' own `theta` and refuses a file that disagrees with itself** — the content hash's cross-check, applied to a rule rather than a hash — and a test pins today's separation, so a re-export that moves a finding between a cut's anchors fails by name (D156). **The harness also refuses a cut the tool could not have drawn, and a band the cuts contradict** (D171): a cut named outside the three, stated twice, inverted or anchored on one finding, a missing cut, or midpoints out of severity order, and a row whose band is not the one its `theta` falls in by the cuts' midpoints, a tie falling to the less severe side as the tool bands it. `run_id` is derived rather than minted — a hash of the log, the anchor set and the cuts — so two exports from an unchanged state carry the same id. `calibration` records what the top cut was drawn against, which is what tells a reader whether a perfectly consistent ordering sits a whole band too high, so the harness surfaces it in severity provenance rather than dropping it. The harness joins on `id`; severity is not a field in the findings document, and the tool never mutates it. **The field list is asserted by `tools/check_spec_interface.py` against the tool's own specification**, because a cross-repository claim held only by two attentive readers has a shelf life measured in hours while both repositories are active. **In CI that assertion is conditional on the sibling being present, and the build fails when it is not.** The workflow checks the sibling out with `continue-on-error`, so that the checkout's own failure does not mask the reason, and then refuses: when the repository is absent the step prints what was not compared and exits non-zero. **This sentence described the opposite until 2026-09-07** — it said the build stays green, and called a harness build that cannot pass without a second repository the worse alternative. That is the trade D84 examined and reversed, after the companion workflow spent a week reporting success while verifying nothing about transcript contents. A conditional check that goes quiet is the failure; a red build naming the missing token is the fix, and the trade-off belongs here and not only in a workflow comment.

## out of scope (v1)
- **Cross-corpus check family** (reachability, cross-call consistency — taxonomy 12, 16, 25) — needs a distinct check shape, result contract and report section rather than another rubric entry. The corpus is nevertheless sized and paired to support them, so adding them later requires no re-authoring.
- **The comparative-judgment severity tool itself** — a standalone product at `hmbseaotter/comparative-judgment`, built before this project starts and linked from this README. Its *method* is in scope and applied here; its code is not.
- **Audio-layer testing** — barge-in, endpointing, ASR and TTS defects do not survive into text. Named as a stated coverage gap, with the follow-up question to be written into phase 6's design document rather than pretended away.
- **A live agent under test** — there is no system being exercised, so agent non-determinism cannot be measured and N-run scenario replay is impossible.
- **Runtime guardrail (preventive control)** — phase 6's design document will specify the shared rule and recommend the implementation, but there is no product to guard.
- **Web UI or dashboard** — the deliverable is a report and a run log; a viewer competes for build time and teaches nothing about evaluation.
- **Non-English corpus** — one language keeps corpus authoring tractable; multilingual evaluation has its own failure modes. The corpus is US English (D44): `en-US`, USD, NANP's reserved `555-0100`–`555-0199` range, and ZIP codes below USPS's lowest assigned code so none can exist.
- **Contract tests against real backends** — the tool layer is mocked by construction; there are no real backends to keep the mocks honest against.

## tools & permissions
n/a (not an agent) — but these bright lines are real and are enforced by requirements below.
- Filesystem: reads corpus and rubric, writes reports and the run log, all under the repo root.
- Network: the Anthropic API only, and only in `--mode live`.
- Credentials: read from the environment or an uncommitted `.env`, under the two declared names `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` and no others — a loader that imported every key it found would be a configuration mechanism nobody asked for. **An exported variable wins over the file**, because a key in the environment was put there for this invocation and a key in a file was put there once; **the value it overrode is still scrubbed**, because a leftover key is still a secret. Each travels under the header the SDK sends its own name as. Never logged, printed, or written to the run log. A value shorter than a declared minimum is not scrubbed at all: an empty or one-character variable matches between every pair of characters and would redact the whole log in the name of protecting it.
- NEVER unattended: a live model call without `--mode live`; committing a populated `.env`; committing anything under `private/`; publishing corpus or findings content derived from prior third-party material.

## state & memory
Stateless between runs, with three persisted artifacts: the frozen extraction artifact (written by `harness.extract` under the ignored `build/`, and re-derived by every run rather than read back, so a result's artifact hash is true by construction), the append-only JSONL run log (one file per run), and generated reports. No cache is consulted across runs except the run log in replay mode, which is addressed by explicit path rather than discovered.

## model & cost routing + determinism boundary
- **Deterministic (plain code, NO LLM):** both parser adapters and wrapped-turn reassembly; every Tier A check; citation validation by set membership; verdict-against-scale validation; the evidence-on-negative-pole guard; roll-up; rate computation over `applicable` results only; rubric schema validation; per-instance severity computed from decomposed boolean properties; report rendering and escaping; run-log writing; request hashing and replay lookup; staleness comparison; snapshot diffing; every log-inspector invariant; coverage arithmetic; agreement statistics.
- **Type & value discipline:** `mypy --strict` over `src/`, `tools/` **and `tests/`** — most of what this project asserts lives in the test suite, and a type check that skipped it would be reporting on the smaller half. The package ships a PEP 561 `py.typed` marker, without which every annotation in it becomes `Any` at an adopter's import site; frozen dataclasses for the Result and every contract type; `typing.Final` for constants; tuples over lists for fixed collections. "type-check passes" is an acceptance criterion.
- **Requires judgment (LLM):** narrowed and sharpened by D42, after a human review rejected several drafted `judge` classifications by name. The rule is that **anything derivable from the context record, tool calls, results, state and their order is `assert`** — a judge must never be asked to evaluate an agent's response against the value of a system variable. What survives is what nothing else can do:
  1. *Were all of the caller's concerns addressed?*
  2. *Did the agent hold a coherent conversation, or repeat itself **unnecessarily**?* — and the qualifier is the whole point. A repeat after a caller whose line broke up, or whose accent or proficiency made them hard to follow, is correct behavior. No counter separates that from a question already answered, which is why the corpus seeds both in one call.
  3. *Did the terms the agent stated in reply to this question align with policy?* — retrieval and quotation are assertable; whether the paraphrase conveyed the rule is not.
  4. *When the caller pushed back on something the agent had said, had the agent understood them?* — **widened at D133 from "when the caller objected and a reversal or transfer followed"**, because the design set contains exactly one reversal and the seeding manifest records it as correct behavior. A reversal is evidence that something went wrong earlier; pushback is the same evidence one step earlier, and it is the step the corpus seeds. The narrower reading survives as the entry's `negative_instance` — CALL-20, the one reversal, is exactly the call the dimension must stay silent on. This also closes taxonomy item 1, *doubling down under correction*, which `specs/taxonomy-coverage.md` recorded as a gap needing either an eighth dimension or an explicit deferral.
  5. *Is a claim plausible against the world rather than only against the payload?* (taxonomy 31)
  6. *Does the agent's confidence exceed what its data sources can support?* (taxonomy 17)

  Plus the call-level synthesis narrative, and at P7 parser-pass normalization of speech into structured claims. **This is a stronger justification for spending model calls than the previous list**, which routed to a judge several things an assertion decides better.
- **Model tier per judgment task:** six judged dimensions<!-- #judged_dimensions --> → `claude-sonnet-5` (bounded calibration against supplied facts, cheapest of the current families). Synthesis → `claude-opus-5` (reasons across every other dimension's result; the part a human reads first). Both configured per rubric entry, never hardcoded at the call site.
- **Generation config:** adaptive thinking; `output_config.effort` per entry; structured output via `output_config.format` with a schema built from the entry's declared scale. Sampling parameters are never sent — `temperature`, `top_p` and `top_k` are **removed on both models this project uses and return a 400**, so this is an API fact rather than a project convention. Determinism for the judged tier comes from replay, never from sampling control; an engineer reaching for `temperature=0` by reflex is reaching for a parameter that does not exist here. A supported-model set is declared, and an unsupported model is refused by name rather than by sending a parameter that returns 400.
- **Cost / budget guardrails:** replay is the default mode and spends nothing; `--mode live` prints an estimated call count and cost and requires confirmation; `--max-calls` caps a run, counting **logical calls rather than HTTP requests** — one call can cost up to the declared transport-attempt ceiling on a transient failure; prompt caching [P6] will apply across the repetitions of one entry on one call, which send one byte-identical request; the transcript block is identical across dimensions too, but each dimension's question sits in the system message ahead of it, so no cached prefix can hold the transcript for more than one dimension until the template is reordered (D204).
- **Stop / escalate when:** call ceiling reached → halt and report; retry budget exhausted → status `errored` for that result, run continues; ground truth absent → status `unevaluable`, recorded with the missing reference.

## constraints
- Stack: Python 3.12+, `uv` with a committed `uv.lock`, `pytest`, `mypy --strict`, `ruff` (lint + format), GitHub Actions.
- Dependencies: PyYAML, **`tzdata`** and the Anthropic SDK, pinned to exact resolved versions in the lockfile. `tzdata` is the IANA time-zone database the CPython team package separately: `zoneinfo` reads the operating system's copy, Windows ships none, and the venue-local date check would therefore pass on the Linux CI runner and fail on the author's machine. A platform-dependent test is worse than either outcome alone, so the database is pinned like everything else rather than inherited from whatever the host happens to have. Approved as a new dependency before it was added, per the rule below. No floors presented as pins — the declaration in `pyproject.toml` states `==` too, so the two files cannot drift into disagreeing about what "pinned" means. **`types-PyYAML`** is added as a dev dependency: it is stubs-only for an already-approved package, and it is the only route to the "`mypy --strict` with no ignored errors" criterion, since PyYAML ships no inline types and the alternative is the `# type: ignore` that criterion forbids.
- Do NOT read the reference implementation during design or build — it is a post-hoc completeness check only.
- Do NOT read, adapt, paraphrase or reuse any prior third-party material, its derived findings, or a prior implementation's pattern lists and tool names. The clean-room boundary is listed in `private/clean-room-sources.md`.
- Follow the substitution-by-class policy for every invented entity. **Seven classes**, each of which must be an invented but plausible substitute wherever it appears in the corpus, the findings document, the rubric or the prose: (1) company, brand and product names, catalog entity names and identifiers; (2) phone numbers, addresses, email addresses, URLs, account and order numbers; (3) prices, totals, tax and fee components, discount amounts, item counts; (4) policy terms — refund and return windows, eligibility rules, SLA and delivery timings, cancellation penalties; (5) named third parties such as carriers, payment processors and banks; (6) tool and action names, variable names, status vocabulary, reason codes; (7) call identifiers and any file naming that mirrors prior material. Class 5 carries an authoring constraint: taxonomy item 31 depends on a third party whose real-world characteristics can be checked, so the substitute must be a real-enough service class with invented specifics, or an invented service with stated characteristics — otherwise that category becomes unjudgeable and the corpus loses its clearest justification for spending a model call.
- The corpus must not merely rename entities but change scenario **shape**: a scenario recognizable as prior art with the nouns swapped is a leak even when every noun is invented. The domain boundary and its concrete smells are recorded in `private/substitution-classes.md`.
- No new packages without flagging for approval first.

## prior decisions
- **Four repositories now, from the three-repo topology** (names settled D19, D20): `hmbseaotter/voice-agent-eval-harness-private`, the working repository, private; `hmbseaotter/voice-agent-eval-harness`, public since 2026-09-21 — a snapshot of one commit rather than this history, because the harness did not flip but was copied (D208); `hmbseaotter/voice-agent-eval-harness-holdout` (private, held-out set — prefix-matched so the two sort adjacently and the pairing needs no explanation); and `hmbseaotter/comparative-judgment`, public since 2026-09-21 with its history (the severity tool, deliberately unprefixed because it is domain-general and does three jobs, none of them voice-specific).
- **Held-out means held out from the design process, not secret**: labels are revealed once the rubric is frozen, in a companion repository public since 2026-09-22, but two distinct properties are secured by two distinct mechanisms, at two distinct moments (D21). *(a) The rubric was not designed against these labels* — secured by the labels not existing until after the `rubric-frozen-v1` tag, with their commit citing the main repository's freeze commit SHA, since a SHA is a content hash and citing it demonstrates knowledge of a specific prior state more strongly than two forgeable timestamps across two repositories. *(b) The labels were not tuned once judge output was visible* — secured by a hash manifest committed after authoring but **before any held-out judged run**, with plaintext published afterwards. Property (a) is evidence, not proof; property (b) is checkable by recomputation.
- **One repo, layered by package and docs routing**: `core/` holds contracts, registry and engine; `corpus/` holds the worked example as the first adapter; a second adapter proves the seam. A core/extensions repo split was rejected — it would move the proof of adaptability out of the repo making the claim, and charge a version-skew tax paid by one maintainer.
- **Corpus: sixteen design calls<!-- #design_set_size --> plus the held-out set, N=10** — 12 design at D4; D68 added two when an error-type sweep found classes the twelve could not carry without becoming implausible, D73 a third for escalation and D119 a fourth. The held-out set grew by one, the escalation call O-3's decision asked for (D83, D86); what O-3 still owes is the statement of which classes the held-out measurement does not reach. N is judge repetitions over a fixed transcript, so for a dimension it measures evaluator variance only, and for the synthesis, each of whose repetitions reads its own resample of the dimensions' answers (D154), it measures that variance together with the variance of its input; any resulting rate describes judge stability and corpus difficulty, never a production failure rate. N=5 was rejected at the assumptions gate as too coarse: five samples resolve only to 20% steps, so a genuinely low-frequency verdict flip may never surface, leaving the sample-not-proof claim unevidenced. N=10 halves the resolution step and raises the chance of observing a 10%-frequency flip from roughly even to about two in three.
- **Independent domain, substitution by class**: the corpus domain is chosen on its own merits rather than adapted from prior art, and seven entity classes are invented wholesale.
- **The domain is event ticketing**: it carries genuine refund, exchange, transfer and name-change policy with hard event deadlines, is plausible for voice support, and supplies natural instances of eligibility preconditions, irreversible writes and time-window rules. Names, dates and venues give the heard-value reconciliation dimension something real to reconcile. It is also structurally unlike the commoner order-management shape — no shipping, no inventory, no goods in transit — which keeps scenarios from being transferable from adjacent prior art. Rejected: travel booking (richest policy surface, but its real intricacy competes for the reader's attention with the evaluation method) and subscription billing (thinner irreversible-action surface, and billing disputes are well-trodden ground).
- **Zero exposure to the source transcripts**: format and corpus are designed independently, so the new corpus's independence is structural rather than a claim about restraint.
- **Status and verdict are separate fields**: `status` ∈ {applicable, not_applicable, unevaluable, errored, refused}; `verdict` populated if and only if `applicable`. `unevaluable` exists because a dimension can apply while no ground truth exists to judge it against — a finding against the corpus, not the call. `refused` exists because the model declining to answer is neither of those and is an expected event on a corpus that seeds prompt injection by design (D23).
- **A judged dimension may never declare an absolute gate**: rejected at rubric validation by name, because an absolute gate must never depend on a live model call.
- **Replay is the default mode**: live requires an explicit flag, so behavior never depends on whether a credential happens to be present in the environment.
- **Apache-2.0 for code, CC BY 4.0 for corpus and docs.**
- **Gold-set human provenance is a validity precondition, not a disclosure courtesy**: model-assisted for the artifact under test, human for the ground truth. Model-generated labels would make "human agreement" measure nothing.
- **No build log was kept, and the decision record is what the project has instead.** D11 put one under `private/` until publication is decided (D10's option (B)), and that directory holds the clean-room sources and the substitution classes alone. An ignored file leaves no record when it goes, so whether one was written and later removed cannot be settled from here; the owner recalls none being needed. The protections D11 and D14 describe stand and are what the pre-publication history scan reads: they are stated here as the mechanism, not as evidence a log exists**, protected by a `private/` gitignore entry naming no filenames, a fail-closed global pre-commit guard, an external backup, and the history scan before publication, which D208 records. **Both pre-commit guards are machine-level controls that this repository provides but cannot install for you** — they live in the global hook because a repo-local `.git/hooks/pre-commit` never fires once `core.hooksPath` is set machine-wide (D14). The hook source ships with a documented one-line setup step; until it is run, a clone has the ignore rules and none of the enforcement. Stating this is not pedantry: the build prompt's own rule is that an unverified guard is worse than none because it is relied upon, and a guard a reader *believes* they have is that hazard one step removed.
- **Severity tool first, then score, then harness**: the findings document is both traceability anchor and gold set, so severity sits upstream of the rubric.
- **Findings are YAML; severity is a separate file joined by id** (D22): evidence fields hold verbatim multi-line quotes and the row schema requires fragments from different points in a call to stay visibly separate — which a Markdown table cell physically cannot do and CSV quoting handles poorly. Severity lives outside the findings document because the tool that produces it must never mutate a document it does not own; keeping it separate also makes severity provenance explicit (which run, which anchor set, which comparison log) rather than an unattributed column edit. **What that provenance does not attest to is the text it scored** (D82), and at D140 the gap produced its first instance: `e28650c` on 2026-09-07, a repository-wide spelling pass, edited three findings that had already been judged, and nothing in this tree could see it, because the per-finding content hashes live only in the tool's own gitignored store. Carrying that hash into the exported file is D82's own rejected option, reopened as OB-18 and taken at D148: the row gained `content_hash` at schema 2, and OB-18 is closed. **Nor does it record how well determined a band is** (D144): a finding placed against the cuts can carry three comparisons where its neighbors carry ten, and `severities` held `id`, `severity` and `theta` with nothing to separate the two until schema 2 added `appearances` and `informative`, which is what separates them now.
- **Sonnet 5 for dimensions, Opus 5 for synthesis**: demonstrates model routing rather than asserting it, and keeps the committed reference run log cheap to regenerate when a prompt changes.

## requirements

### ubiquitous (always active)
- The system SHALL [P2] represent every check result with a `status` field drawn from `{applicable, not_applicable, unevaluable, errored, refused}` and a `verdict` field populated if and only if `status` is `applicable`.
- The system SHALL [P2] stamp every result with the rubric version, the corpus version and the content hash of the frozen extraction artifact it was computed from.
- The system SHALL [P2] treat the system-level event log and retrieved policy clauses as ground truth, and agent speech as the subject under test.
- The system SHALL [P2] read every check parameter, threshold, signal list and model identifier from the rubric entry, with no such value hardcoded in Python.
- The system SHALL [P2] pass `mypy --strict` with no ignored errors, and SHALL declare contract types as frozen dataclasses and fixed constants as `typing.Final`.
- The system SHALL [P3] record, for every judged call, the exact prompt sent, the raw response received, the model identifier, the generation configuration, the retry count, timings and token counts, appended to a per-run JSONL log.
- The system SHALL [P3] exclude credential values from every log, report, error message and run-log entry.
- The system SHALL [P1] contain no transcript text, finding text, entity name, figure or policy term derived from prior third-party material.
- The system SHALL [P1] read the findings document as YAML, requiring on every entry a stable `id`, `call_ref`, `owner`, `observation`, `evidence` as a list, `consequence`, `detectable_by` and `tier`. `owner` is `agent` | `platform` | `data` (D43): a row bundling a platform defect with an agent defect is actionable by nobody. `owner` and `call_ref` were enforced by the loader and required by nothing in this document, so a findings file built to this specification was rejected by the code implementing it.
- The system SHALL [P1] resolve a finding's severity by joining the separate severity file on `id`, and SHALL NOT read a severity field from the findings document.

- WHEN [P2] a rubric entry declares `tier: judge` together with `gate: absolute`, the system SHALL reject the rubric and SHALL name that entry identifier and the reason.
- WHEN [P2] a check returns `status: applicable` with a verdict absent from that entry's declared scale, the system SHALL raise an error naming the entry identifier and the offending verdict.
- WHEN [P2] a check returns the scale member declared negative for its entry with an empty evidence list, the system SHALL raise an error naming the entry identifier.
- WHEN [P1] extraction encounters a tool status token outside the declared closed vocabulary, the system SHALL abort naming the transcript file, the source line number and the token.
- WHEN [P1] extraction cannot parse a line, the system SHALL increment an unparsed-line counter and SHALL report a non-zero count as a failure rather than discarding the line silently.
- WHEN [P3] a judged response cites an identifier absent from the citable universe, the system SHALL retry once with the rejected identifiers and the full valid identifier set included in the retry prompt. WHEN a judged response cannot be read as the declared schema, or fails more than one check, the system SHALL spend the same single retry and SHALL name every failure it found rather than the first, and never an empty rejected-identifier list (D179). *(The second clause was behavior with no requirement until 2026-09-09: a malformed response bought the retry, and the correction it carried read "cited identifiers that were not in this prompt: ." — the citation wording with nothing in it.)*
- WHEN [P3] the retry budget for a judged dimension is exhausted, the system SHALL return `status: errored` for that result and SHALL continue the run.
- WHEN [P3] a judged response carries `stop_reason: "refusal"`, the system SHALL return `status: refused` for that result, SHALL record `stop_details.category` and `stop_details.explanation` in the run log, SHALL NOT consume the retry budget, and SHALL continue the run.
- WHEN [P3] a judged response carries `stop_reason: "max_tokens"`, the system SHALL return `status: errored` for that result and SHALL record the stop reason, so truncation is distinguishable from a validation failure by log inspection alone.
- WHEN [P3] any judged call returns, the system SHALL record its `stop_reason` in the run log unconditionally, alongside the generation configuration.
- WHEN [P3] a live run has issued as many calls as the configured ceiling, the system SHALL halt and report without issuing a further call.
- WHEN [P3] the model transport returns a transient error, the system SHALL retry with exponential backoff to a declared maximum, and SHALL persist results already obtained before any subsequent abort.
- WHEN [P3] the system runs in replay mode and a request hash is absent from the run log, the system SHALL abort reporting the missing hash and SHALL NOT issue a live call.
- WHEN [P3] the system runs in replay mode and the run log's rubric version or prompt-template hash differs from the current value, the system SHALL abort unless `--allow-stale-replay` is supplied.
- WHEN [P4] the synthesis dimension cites a rubric identifier that did not produce a result in the same run, the system SHALL report that citation as a defect.
- WHEN [P5] judge validation runs, the system SHALL report agreement against human labels separately for the design set and the held-out set, SHALL report for each rubric entry the calls it fired on that carry a finding traced to it, the calls it was silent on that do, the calls it fired on that do not, the calls it was silent on that do not, and the calls it gave no verdict on by status, each set over its own call count, SHALL take a judged entry as firing where its gate reads a violation, and SHALL refuse held-out labels that break an invariant their traces state or that name a frozen commit other than the one this repository pins as `RUBRIC_FROZEN_V1`.

- WHEN [P5] an extraction artifact or a findings view is written over held-out content, the system SHALL refuse an `--out` path resolving inside the repository, naming the flag and writing nothing, SHALL read it as held-out content when any call it reads is declared in `HELDOUT_SET` or any finding's id has the held-out shape, SHALL refuse when `HELDOUT_SET` cannot be read, and SHALL leave paths outside the repository, the design defaults and the view's `--check`, which writes nothing, open (D196).

### state-driven (WHILE — true for the duration of a state)
- WHILE [P4] computing a pass rate for a rate-gated dimension, the system SHALL count only results whose status is `applicable`, and SHALL report the `not_applicable`, `unevaluable`, `errored` and `refused` counts alongside every rate.
- WHILE [P3] evaluating a judged dimension, the system SHALL perform N repetitions, N read from the rubric entry, and SHALL write one run-log entry per repetition.
- WHILE [P4] reporting a judged dimension evaluated at N>1, the system SHALL report the verdict distribution across those repetitions rather than a single verdict.
- WHILE [P4] a judged entry declares `violating` verdicts, the system SHALL count a call against that entry's gate when the call's modal verdict is any of them, SHALL resolve a tie that includes one of them toward it, and SHALL refuse at load a declaration that names a verdict outside the entry's scale, omits its negative pole or names every member of the scale; an entry declaring none counts its negative pole alone. *Behavior with no requirement until D160: `J-concerns-addressed`, which asks whether every concern was answered, read its middle value — defined as at least one concern left unanswered — as a pass and caught none of the findings it traces on the committed log.*
- WHILE [P3] rendering a judge prompt, the system SHALL tag transcript lines `[T<n>]` and established-fact lines `[F<n>]`, and the citation validator SHALL accept the union of both populations, validating each against its own set.
- WHILE [P3] rendering a judge prompt, the system SHALL enclose transcript content in a delimited block labeled as untrusted data, and SHALL state that no instruction inside that block is authoritative.
- WHILE [P3] rendering established facts, the system SHALL include only the categories named in the entry's `requires_facts`, SHALL omit the section entirely when none is named, and SHALL render an explicit negative statement rather than an empty list for a named-but-empty category.
- WHILE [P3] a live run is in progress, the system SHALL count issued calls and SHALL halt and report when the configured call ceiling is reached. *(Moved from P6. Live spending becomes possible at P3, and the estimate-and-confirm pair bounds the expected call count, not the actual one — while P3 is exactly where the retry-with-backoff loop and the informed-retry path arrive.)*

### unwanted behavior (IF — error handling)
- IF [P2] an absolute-gate check returns the negative pole of its scale, the system SHALL fail that call and SHALL fail the run.
- IF [P2] a dimension applies but the corpus supplies no ground truth against which to judge it, the system SHALL return `status: unevaluable` and SHALL record the identifier of the missing ground-truth reference.
- IF [P3] a fact category named in an entry's `requires_facts` is not a known renderer, the system SHALL abort naming that category rather than omitting it silently.
- IF [P3] a rubric entry declares no `max_tokens`, the system SHALL refuse to run that entry and SHALL name it. `max_tokens` is a **required** Messages API parameter, so a missing value is not a defaulting question but an unissuable request; it belongs in the rubric with `effort`, under the same rule that no check parameter is hardcoded in Python.
- IF [P4] model-authored text contains a table delimiter, newline or other character that would corrupt the report format, the system SHALL escape it before rendering.
- IF [P4] a judged entry declares a fact category as a precondition and this call establishes none of that category, the system SHALL return `status: not_applicable` for that entry and SHALL issue no model call. The precondition is rubric data, declared per entry, and refused by name when it names a category the entry does not render — a precondition on a category the prompt never carries is a precondition on nothing. *This was behavior with no requirement until D132: the judged tier had no way to say a dimension does not apply to a call, so a dimension whose subject was absent answered anyway — reproducibly, across every live pass, against a clause set that was empty.*
- IF [P1] a staged path lies under `private/`, the pre-commit guard SHALL block the commit, SHALL name the path, and SHALL also block when the path cannot be resolved or the staged entry cannot be read. This is the guard protecting the build log that D11 and D14 exist to keep out of a history published retroactively, which is why its fail-closed clause is stated here rather than left to the `.env` guard's precedent.
- IF [P1] a staged file is named exactly `.env` and its staged blob exceeds 20 bytes, the pre-commit guard SHALL block the commit, and SHALL also block when the blob size cannot be determined.

### non-functional
- Security: the system SHALL splice no raw caller or agent speech into a judge prompt outside the delimited untrusted block, and SHALL keep the citable-identifier syntax distinguishable between transcript and fact populations. [P3]
- Security: the repository SHALL contain a `.gitignore` covering at minimum `.env`, `private/`, `__pycache__/` and `*.pyc` in its first commit. [P1]
- Performance: a full replay-mode run over the sixteen-call design set<!-- #design_set_size --> SHALL complete without network access. [P3]
- Performance / transport posture: the system SHALL declare an explicit per-request client timeout rather than inheriting the SDK's 10-minute default, and SHALL state whether the specified exponential backoff **replaces** the SDK's own automatic retries or wraps them. A full live design-set run is on the order of a thousand judged calls — sixteen transcripts x 6 dimensions x N=10, plus synthesis, **less the calls each entry's precondition excludes** (D132). De-quantified deliberately: the exact figure moved when the precondition landed and `J-policy-alignment` stopped applying to the design calls that retrieved no policy, and it is computed from the rubric and the corpus by `judged_call_estimate` rather than written here twice. Each call carries a whole transcript; two retry mechanisms layered by accident multiply the wall-clock cost of every failure. Streaming is not required, but a request whose `max_tokens` is large enough to risk the non-streaming timeout SHALL stream. [P3]
- Error handling / observability: the system SHALL emit a run log sufficient to reproduce any judged result, and the log inspector SHALL assert invariants over it emitting metrics rather than scores. [P6]
- Reproducibility: the Tier A section of the report SHALL be byte-identical across repeated runs in both modes, and the full report SHALL be byte-identical across repeated runs in replay mode. [P4]
- Privacy: the corpus SHALL contain no real personal data, and every entity SHALL be an invented substitute under the declared substitution classes. [P1]

## failure & escalation
- Recoverable error: transient transport failures retry with exponential backoff to a declared maximum; a citation failure triggers exactly one informed retry.
- Unrecoverable error: rubric schema violation, unknown fact renderer, unknown status token, replay cache miss and replay staleness all abort the run with a named cause; results already computed are persisted first.
- Stuck / uncertain: a judged dimension that cannot produce a valid result within its retry budget resolves to `status: errored` rather than to a verdict; a dimension with no ground truth resolves to `status: unevaluable`; a response the model declines to give resolves to `status: refused`. None is silently treated as a pass, and none is conflated with another — a harness whose thesis is that evaluation must distinguish failure modes cannot report three of them as one.
- Escalation channel: non-zero exit code plus a named cause on stderr, and the run log retained for inspection. **Both tiers use one code vocabulary** (D114, extended to the judged tier at D127): `0` the tier ran, `2` the run could not be made — a rubric that does not load, a missing or stale replay log, no credential in live mode, an unknown fact renderer, a confirmation not given — and `3` the tier ran and could not be completed, which is a judged run that aborted part-way or one carrying `errored` or `unevaluable` results. `1` is a finding about the agent: a deterministic gate that failed, or, from P4, a judged rate gate below its threshold (D134).

## implementation phases

### phase 1 — corpus, findings, ground truth and a working parser
- Goal: the inputs everything downstream traces to, the repo-hygiene floor, and something that actually executes by the end of the phase.
- Includes (required floor): format specification; taxonomy-to-ticketing scenario map; sixteen design transcripts; reference policy documents<!-- #design_set_size -->; findings document; severity backfill from the external tool; `.gitignore`; both licenses; the `.env` and `private/` pre-commit guards.
- Includes (chosen optional): the extraction tier pulled forward from phase 2, so the phase ends with transcripts parsing and a frozen artifact emitted; decision records accumulated during the work, the design document they feed deferred to phase 6 (D200); the held-out transcripts authored now and placed straight into the companion repository, labels withheld.
- Deferred by choice: the README skeleton with two-audience docs routing — a README written before the artifact exists describes an intention rather than a thing, so it moves to phase 6 alongside the rest of the docs routing.
- Done when: its tagged acceptance criteria pass, and every design transcript parses with a zero unparsed-line count.
- Prerequisite (outside this spec): the comparative-judgment severity tool exists and has scored the design-set findings.

### phase 2 — deterministic evaluation slice
- Goal: a full deterministic evaluation runs end to end with no model call. Extraction already landed in phase 1, so this phase is contracts and checks.
- Includes: Result contract with the five-value status channel, rubric loader and schema validator, Tier A checks reading every parameter from the rubric, roll-up, CLI with `--tier assert`.
- Done when: `--tier assert` executes over the design set with zero model calls, asserted by a transport spy, and its verdicts agree with the gold set. **"Green" is agreement, not a zero exit code** (D105): this corpus is seeded with defects by construction, so an absolute gate firing on it is the tier working rather than failing. A run that exited zero over this corpus would be reporting the W11 fail-open, which is the defect the five-value status channel exists to prevent.

### phase 3 — the judged tier, one dimension deep
- Goal: the expensive half, proven once before it is replicated.
- Includes: transport seam (live + replay), run log, staleness refusal, tagged citation universe, injection mitigation, set-membership validation, informed retry, `errored` on exhaustion.
- Done when: one dimension runs live and replays deterministically.

### phase 4 — full rubric, report and snapshots
- Goal: every remaining dimension added as data, not plumbing.
- Includes: five further judged dimensions, synthesis dimension with citation checking, two-audience report, snapshot tests at their correct scopes.
- Done when: adding a dimension required no engine change.

### phase 5 — held-out labels and validation
- Goal: the claims become measured rather than asserted. The held-out transcripts were authored in phase 1; only their labels are produced here, after the freeze.
- Includes, strictly in this order: the `rubric-frozen-v1` tag; held-out labels authored afterwards, their commit citing the freeze SHA; a hash manifest of those labels committed before any held-out judged run; the judged run itself; then published plaintext labels, agreement measurement and coverage by severity. The ordering is the mechanism, so a phase that produces the right artifacts in the wrong order has not met its goal.
- Done when: agreement is reported per set with its denominator, and the commit-order assertion passes against git history.

### phase 6 — hardening, adaptability and self-inspection
- Goal: the properties a reader will test.
- Includes: second adapter, log inspector, per-instance severity, prompt caching, judge-model comparison, the design document (D200), docs routing. The cost ceiling this list named was built at phase 3 and its expected figure at phase 4 (D152, D161, D170).
- Done when: its tagged acceptance criteria pass, and for every design call the second adapter's event stream differs from the text adapter's only where a declared gap names what the source cannot carry (D203).

### phase 7 — LLM-as-parser
- Goal: the designed-but-never-built stage, finally built and measured, and the deterministic tier moved onto it (D191).
- Includes: two-pass normalization, deterministic verification, precision/recall against the labeled set; the deterministic entries reading the parser's structured claims in place of enumerated phrases, triggers and topics; the reason-code and outcome tables re-expressed or explicitly deferred; and a fresh, larger held-out set authored and labeled blind to that tier, through the same label chain as the first.
- Done when: its precision and recall are reported, not merely its existence, and coverage by severity is reported on the fresh held-out set for the tier reading the parser's claims (D191).
